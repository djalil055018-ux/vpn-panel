# Control Plane lifecycle tool 0.1.0

`platform-lifecycle.py` builds and verifies Linux amd64 release bundles and manages an installation after explicit adoption. It never prints environment values, database contents, administrator tokens, webhook secrets, certificate keys or subscription URLs.

## Release build

Run on Ubuntu 24.04 amd64 with Go 1.27, Node.js 24 and npm available. The default build runs all Go tests and `go vet`, builds every Control Plane worker with `-trimpath` and an empty Go build ID, and packages the web source with its exact lock file. On the target, the web application is rebuilt from that lock file with Next.js standalone output. Only the traced runtime is installed; development dependencies and the full build tree are left in the temporary build directory.

```text
python3 platform-lifecycle.py build --source /opt/vpn-platform --version 0.1.73 --output /root/vpn-platform-0.1.73.tgz
python3 platform-lifecycle.py verify --bundle /root/vpn-platform-0.1.73.tgz --sha256 TRUSTED_SHA256
```

The manifest protects every member from accidental or partial corruption. Mutating commands also require the SHA-256 received through a trusted release channel; an internal manifest alone cannot authenticate a maliciously replaced bundle. The gzip/tar metadata and file ordering are deterministic. Set `SOURCE_DATE_EPOCH` to keep the manifest timestamp deterministic as well. With the same source, toolchain, environment and epoch, the bundle is byte-identical. Go binaries are stripped of host paths and random build IDs. Next.js is reproducible at the dependency-selection level through `npm ci`; its generated bytes are not claimed to be bit-for-bit reproducible.

## Existing production installation

Adoption records the already applied schema without replaying migrations. It requires the running health version and the bundle version to match.

```text
install -m 700 platform-lifecycle.py /usr/local/libexec/vpn-platform/platform-lifecycle.py
python3 /usr/local/libexec/vpn-platform/platform-lifecycle.py adopt --bundle /root/vpn-platform-0.1.73.tgz --sha256 TRUSTED_SHA256 --schema 38
python3 /usr/local/libexec/vpn-platform/platform-lifecycle.py status
```

Use `upgrade` for a different version and `repair` for the managed version. Every update is serialized with a host lock. The bundle is fully checked and its web UI is built before production files change. On an existing installation, the tool then creates and verifies a managed database/configuration backup, saves an application rollback archive, and arms a ten-minute systemd rollback guard. It applies only numbered migrations above the recorded schema, records progress after every successful migration, atomically replaces binaries, installs source and service definitions, and checks the Control Plane, web UI and timers before committing. A failed first installation can be resumed with the same bundle and trusted digest.

```text
python3 /usr/local/libexec/vpn-platform/platform-lifecycle.py upgrade --bundle /root/vpn-platform-0.1.74.tgz --sha256 TRUSTED_SHA256
python3 /usr/local/libexec/vpn-platform/platform-lifecycle.py repair --bundle /root/vpn-platform-0.1.73.tgz --sha256 TRUSTED_SHA256
python3 /usr/local/libexec/vpn-platform/platform-lifecycle.py rollback --backup BACKUP_ID
```

Rollback restores application binaries, source, web runtime and unit definitions. A standalone snapshot starts directly from its archived runtime; rollback to an older snapshot reinstalls its exact locked web dependencies. Applied database migrations remain because release migrations must be additive and forward compatible; lifecycle state retains the highest applied schema number so a later upgrade cannot replay a migration. Stop client/admin writes before a manual downgrade whose older application cannot tolerate the newer schema.

## Prepared-host installation

`install` is intentionally for a prepared Ubuntu 24.04 amd64 host. The host must already have systemd, Docker, Python 3, Node.js/npm, a reachable container named `vpn-platform-postgres`, and root-owned mode-0600 `/etc/vpn-platform/control-plane.env` and `/etc/vpn-platform/web.env`. Those files must contain the environment documented for the services. The tool creates service users, applies all migrations, installs the package and enables the core services and timers. It does not create credentials, expose HTTP publicly, obtain DNS/certificates, configure a firewall, provision Docker/PostgreSQL, or restore production data. Those host-specific operations remain explicit to avoid guessing security and networking choices.

Before using `install` on a replacement server, validate DNS, firewall, reverse proxy, PostgreSQL retention, offsite backup access and the restore/runbook separately. This first release automates application lifecycle, not bare-metal recovery or multi-host failover.
